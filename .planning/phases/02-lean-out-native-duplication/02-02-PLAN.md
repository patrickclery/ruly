<objective>
Remove the three commands that sit outside rule composition or duplicate native tooling, and add the warn-and-continue guard for recipe keys:
- `ruly import` (D-02): `squash` already copies a recipe's scripts.
- `ruly mcp` (D-04): Claude Code manages `.mcp.json` natively; per-recipe `mcp_servers:` stays.
- `ruly analyze` (D-03): folded into `ruly stats`, which becomes the single token-reporting command. Interpretation recorded for AUDIT.md: `stats` already writes per-file token counts and per-recipe totals and prints the recipe total on stdout, so the fold moves Analyzer's console summary into Stats and drops Analyzer's context-window percentages (`--tier`, recipe and config `tier:`, `lib/ruly/contexts.yml`, whose model tiers date from Dec 2024).
- Removed or unknown recipe keys (D-11): squash warns on stderr and continues.

Decision IDs index the bullets of `02-CONTEXT.md` `<decisions>` in document order (D-01 taskmaster ... D-13 shell_gpt/cursor discretion), as listed in 02-01-PLAN.md.

Purpose: leave `squash`, `clean`, `list-recipes`, `introspect`, `init`, `version`, `stats` as the whole command surface, and make dead recipe keys visible instead of silently inert.
Output: CLI without import/mcp/analyze; Stats owns the console summary; Analyzer and contexts.yml deleted; recipe key warnings with specs.
</objective>
