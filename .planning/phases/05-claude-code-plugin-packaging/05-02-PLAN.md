<objective>
Add the `claude-plugin` output target, part 2: map every remaining recipe component into the plugin directory. Skills, commands and subagents go to `skills/`, `commands/` and `agents/` (D-04); hooks go to `hooks/hooks.json` and MCP servers to `.mcp.json` (D-05); scripts go to `scripts/` with references rewritten through `${CLAUDE_PLUGIN_ROOT}` (D-06). Literal MCP secrets are named before the plugin is shared, and recipe parts a plugin cannot carry are named in one notice. The full fixture plugin passes `claude plugin validate --strict` (D-10).

Decision IDs are the same index as plan 05-01 (bullets of `05-CONTEXT.md` `<decisions>` in document order): D-04 component mapping, D-05 hooks and MCP, D-06 scripts, D-10 validation. D-08 (always-on YES branch) stays unimplemented: research verdict NO.

Discretion choices made here:
- Plugin agent `skills:` entries use the namespaced form `PLUGIN:skill` (PLUGIN = recipe name), emitted as a YAML list. [ASSUMED] A3: the sub-agents docs say preloading "draws from the same set of skills Claude can invoke", and plugin skills are invoked as `<plugin>:<name>`, so the namespaced form is the documented identity; a bare name would only work if Claude Code also resolves unqualified names inside a plugin, which no doc states. A missing name is skipped silently ("Claude Code skips it and logs a warning to the debug log"), so this is recorded as a post-run human verification item, not a blocking checkpoint (unattended run). If it fails, switching to bare names is a one-line change in `SubagentProcessor`.
- Nested skill names are flattened for the plugin only (strip a trailing `/SKILL`, then `/` becomes `-`) [ASSUMED A1: nested `skills/a/b/SKILL.md` is undocumented for plugins]; duplicate flattened names warn; a collision with `RECIPE-rules` is an error. The claude target keeps today's nested layout.
- Script references are rewritten only for scripts actually copied into `DIR/scripts/`; other `.claude/scripts/` references are left alone (hook commands warn about them), so a rule that points at a script installed some other way is not broken.
- The literal-secret warning covers `env` and `headers` values that are non-empty strings without `${`. [ASSUMED A2: `${VAR}` in a plugin `.mcp.json` expands like a project `.mcp.json`; the warning stands either way.]
- `marketplace.json` is not generated (D-11), and no SessionStart hook, CLAUDE.md or output style is emitted (D-07 verdict).

Purpose: one native, shareable plugin directory carries the whole recipe, while the default `.claude/` output stays untouched.
Output: `ClaudePlugin` hooks/MCP/scripts/validation methods, `SubagentProcessor` plugin mode, `ScriptManager` directory keywords, CLI wiring, specs.
</objective>
