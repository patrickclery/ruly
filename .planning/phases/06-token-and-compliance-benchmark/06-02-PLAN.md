<objective>
Build the compliance benchmark harness: eight tasks, each testing one fixture rule with deterministic checks on Claude's reply, run under two conditions (ruly recipe-scoped CLAUDE.local.md vs the native rules + skills layout of the same corpus) through headless `claude -p`. This phase ships the harness and proves its wiring with a dry run; the paid live run is left to the user.

Decision IDs index the `<decisions>` bullets of `06-CONTEXT.md` in document order (full list in 06-01-PLAN.md objective). This plan implements D-05 (headless `claude -p`, at most 10 tasks, deterministic checks), D-06 (two conditions), D-07 (no live run here; `--dry-run` validates wiring), D-08 (default model `claude-sonnet-5-5`, configurable) and D-11 (task wording), and carries the D-03 privacy rule over to live runs.

Discretion choices made here (D-11 and gaps the decisions leave open):
- Dry run is the default mode, and `--dry-run` is accepted explicitly; `--live` is the only way to spend money.
- Checks: `forbid` (regex must not match) and `require` (regex must match), over scope `text` (whole reply), `code` (contents of all fenced blocks joined by newlines, or the whole reply when there is none) or `first_line` (first non-blank line of the `code` scope, stripped). Patterns are compiled with `Regexp.new` and no flags.
- Each task carries `example_pass` and `example_fail` replies; the dry run requires every check to pass on example_pass and at least one to fail on example_fail, so scoring is proven without an API call.
- Native layout: path-scoped and always-loaded rules go to `.claude/rules/` with the path flattened (`ruby/style.md` becomes `ruby-style.md`), so no claim about nested rule dirs is needed; skills go to `.claude/skills/<derive_skill_name>/SKILL.md`; commands to `.claude/commands/<path after commands/>`. Rule files keep `paths:` and lose `requires:` (`strip_metadata(keep_frontmatter: true)`); skills and commands keep `name:`/`description:` (`strip_metadata`).
- Live call shape, flags verified against `claude --help` on 2026-11-02: `claude -p --model MODEL --output-format json --setting-sources project,local --no-session-persistence --max-budget-usd CAP --disallowedTools Edit,Write,Bash,NotebookEdit`, prompt on stdin (the variadic `--disallowedTools` comes last so nothing positional follows it). `--setting-sources project,local` keeps user-level settings out; whether user memory (~/.claude/CLAUDE.md) also stays out is unverified, so `--isolated-home` runs claude with a temp HOME (API-key auth only) for a clean run.

Purpose: measure whether recipe scoping changes rule compliance, not just tokens (research "Strategic options" #3).
Output: harness code, task suite, specs. No results files.
</objective>
