<domain>
## Phase Boundary

Add an `agents` output target so `ruly squash RECIPE -a agents` writes the recipe's squashed body to `AGENTS.md`, letting any AGENTS.md-aware agent consume ruly recipes without per-agent adapters. Recipe composition (files, `requires:`, overrides) stays ruly's layer. No fan-out to other agent formats (that is Ruler/rulesync's job).

</domain>

<decisions>
## Implementation Decisions

### Invocation
- New agent value `agents` (alias `agents-md`, `agentsmd` normalized in `normalize_agent`)
- Default output file for `-a agents` is `AGENTS.md`; `-o` still overrides
- No new top-level command, no new recipe key — reuse `--agent` (minimal design surface)

### Content
- Body = the same squashed markdown as the Claude output (rules + `requires:` resolved, frontmatter stripped)
- Skills: inline skill bodies as sections under a `## Skills` heading (AGENTS.md has no on-demand skill mechanism); commands and subagents are NOT emitted (Claude-specific) — print a one-line notice listing what was skipped
- Hooks, MCP servers, settings: not emitted for `agents` target; notice line only
- Prepend a one-line generated-file comment (`<!-- Generated by ruly from recipe: NAME — do not edit -->`)

### Cursor
- Keep the existing cursor target unchanged this phase; note in README that `AGENTS.md` is the recommended cross-agent path. Removal of cursor is deferred.

### Clean / Git
- `ruly clean -a agents` removes `AGENTS.md`; `--git-ignore`/`--git-exclude` include it
- Post-squash checks (ambiguous links etc.) run on AGENTS.md output too

### Claude's Discretion
- Exact notice wording; whether skills are inlined in a `<details>` block or plain sections (prefer plain sections)

</decisions>
