# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.4.0] - 2026-11-02

Ruly can package a recipe as a Claude Code plugin directory, to load with `claude --plugin-dir` or
share.

### Added

- `ruly squash RECIPE -a claude-plugin` writes a Claude Code plugin directory (`ruly-plugin-RECIPE/`,
  or the directory given with `-o`) with `.claude-plugin/plugin.json`, the squashed rules as the
  skill `RECIPE-rules`, the recipe's skills (nested names flattened), commands, subagents as plugin
  agents, `hooks/hooks.json`, `scripts/` and `.mcp.json`. Script references are rewritten to
  `${CLAUDE_PLUGIN_ROOT}/scripts/`; in hook commands the rewrite respects shell quoting and also
  covers `./.claude/scripts/` and `$CLAUDE_PROJECT_DIR/.claude/scripts/`, and any other
  `.claude/scripts/` reference left in a hook is named on stderr.
- The `claude-plugin` target prints a notice that plugins cannot carry always-on rules, so the rules
  ship as skill `/RECIPE:RECIPE-rules` and `ruly squash RECIPE` (CLAUDE.local.md) is still needed for
  always-on rules.
- The `claude-plugin` target prints one line naming what it skipped (`model`, `isolate`, subagent
  `permissionMode`, subagent cwd hooks).
- Squash warns when `.mcp.json` servers have literal `env` / `headers` values or secret-looking
  `args` / `url` values, naming the servers only, never the values.
- `ruly squash -a claude-plugin` refuses a directory ruly did not generate, the working directory,
  its parents and `$HOME` (symlinks resolved), and a `-o` path starting with `~`. A failed build keeps
  the previous plugin. Recipe and subagent skill names are checked before they are written.
  `ruly clean RECIPE -a claude-plugin` removes only a ruly-generated plugin directory and never
  `.claude/`.
- `-i` / `-I` add the plugin directory to `.gitignore` / `.git/info/exclude`.

### Changed

- Squash refuses a subagent name that is not letters, digits, `.`, `_` and `-` (or holds `..`)
  before writing anything, for every target that writes subagents. Such a name could write the agent
  file outside `.claude/agents/`.

### Known limitations

- The `claude-plugin` manifest `version` is always the ruly version, so re-squashed rules do not
  reach marketplace or git installs until the version changes. See the README.

## [0.3.0] - 2026-11-02

Ruly can write a recipe to `AGENTS.md`, the cross-agent instruction file standard, so agents other
than Claude Code can read the same rules.

### Added

- `ruly squash RECIPE -a agents` (aliases `agents-md`, `agentsmd`) writes `AGENTS.md`, or the path
  given with `-o`. Line 1 is the header `<!-- Generated by ruly from recipe: NAME — do not edit -->`,
  followed by the same squashed rules `CLAUDE.local.md` gets and the recipe's skills as plain
  sections under `## Skills`. Rule frontmatter is stripped, including the `name:` / `description:`
  directives `CLAUDE.local.md` keeps (`--front-matter` keeps it).
- The `agents` target skips Claude-only parts (commands, subagents, hooks, `mcp_servers`, `model`,
  `isolate`) and prints one line naming what it skipped.
- `ruly clean -a agents` removes `AGENTS.md` only when it carries the ruly header, and leaves
  `.claude/`, `.mcp.json` and `CLAUDE.local.md` alone.
- `ruly squash -a agents` refuses to overwrite an `AGENTS.md` that does not start with the ruly
  header. The check runs before `--clean` / `--deepclean`, so a refused squash deletes nothing, and
  ignores a UTF-8 BOM before the header.
- `-i` / `-I` add `AGENTS.md` to `.gitignore` / `.git/info/exclude`, plus each recipe script the
  `agents` target copies to `.claude/scripts/` (where `AGENTS.md` refers to it).

### Changed

- `-i` / `-I` merge new entries into the existing `# Ruly generated files` section instead of
  replacing it, so running one target with `-i` no longer un-ignores another target's output.
  Entries already in the section are kept; remove stale ones by hand.

### Fixed

- `ruly.gemspec` now takes its version from `Ruly::VERSION` (it still said 0.1.0).

## [0.2.0] - 2026-11-02

Ruly drops commands, flags and outputs that are unrelated to rule composition or duplicate native
Claude Code features. Removals are immediate, with no deprecation period.

### Removed

- `ruly import` command. `ruly squash` already copies recipe scripts to `.claude/scripts/`.
- `ruly analyze` command and its `--tier` / `--all` options. Use `ruly stats`, which now prints the
  console token summary.
- `ruly mcp` command. Choose MCP servers per recipe with `mcp_servers:` (written to `.mcp.json` by
  `ruly squash`), or use Claude Code's `claude mcp add`.
- `squash --cache` and its cache output (`cache/<agent>/<recipe>.md`, `~/.cache/ruly/`).
- The `-T` / `--taskmaster-config` flag on `squash` and `clean`, and `squash --keep-taskmaster`,
  including the `.taskmaster/` config copy and import.
- Shell-GPT role-JSON output. `-a shell_gpt` and `-a sgpt` now produce plain markdown, like other
  non-Claude agents, and print a notice on stderr saying so.
- The `tier` recipe and config key, and `lib/ruly/contexts.yml` (context-window tier percentages).

### Changed

- Unknown CLI switches now exit 1 with `Unknown switches` instead of being ignored.
- `ruly <command> --help` and `ruly <command> -h` show that command's help (same as
  `ruly help <command>`).
- `ruly squash` warns on stderr about removed or unknown recipe keys (for example `tier`, or a
  misspelled `omitCommandPrefix`) and continues. A top-level `tier:` in the recipes config file
  warns the same way.
- `ruly stats` is the single token-reporting command.
- `ruly list-recipes` no longer prints a `Tier:` line.

### Fixed

- `ruly stats` no longer aborts when no recipe source is configured. It writes `stats.md` for the
  local rule files and warns on stderr that recipe totals are skipped.

## [0.1.0] - 2024-08-19

### Added

- Initial release of Ruly as a Ruby gem
- `ruly import` command to generate CLAUDE.local.md with @import statements
- `ruly squash` command to combine all markdown files into one
- `ruly list-recipes` command to list available recipe collections
- `ruly init` command to initialize ruly in a project
- `ruly version` command to show the version
- Recipe-based compilation system with YAML configuration
- Support for Claude and Cursor AI assistants
- Caching system for recipe compilation
- Command file separation for Claude assistant

### Changed

- Migrated from shell script installer to Ruby gem distribution
- Changed from symlink-based system to gem-based distribution
- Made `ruly` available in PATH when installed as a gem

### Removed

- Shell script installer (install.sh)
- Symlink-based global rules system
- Direct file system manipulation approach
